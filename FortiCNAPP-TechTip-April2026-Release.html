Generally Available — April 2026

Feature 1 of 11 GA Azure · Cloud Coverage
New Azure Service Coverage Added

FortiCNAPP has added support for a new Azure service datasource, expanding CSPM and resource inventory coverage for Azure environments:

  • Application: microsoft.applications/list_applications

This datasource provides FortiCNAPP with visibility into Azure Active Directory (Entra ID) registered applications — including app registrations, service principals, and OAuth 2.0 application objects. This enables CSPM policies to assess application registration misconfigurations, overly permissive API permissions, and credential hygiene for registered applications.

Privilege update required: The introduction of this new service may require you to modify the privileges of the FortiCNAPP user in your Azure cloud account. See Maintain Cloud Integrations with Terraform for update procedures.

Feature 2 of 11 GA Platform UX · Alerts
New Feature: Interactive Time Chart in Alert Dashboard

The Alerts by Severity chart in the Alerts dashboard is now interactive, making it significantly easier to investigate alert activity over time.

What's new

  • Click-to-zoom filtering: Click any time window in the chart to filter alerts to that specific period — no manual date filter adjustment required
  • Visual indicators: Hover states and pointer cursor clearly indicate which chart areas are clickable
  • Automatic refresh: Chart selections automatically update the date range filter and all displayed alert data
Investigation workflow impact: Alert spikes are a primary SOC investigation trigger. Previously, identifying the time window of a spike and then filtering to it required two manual steps. Click-to-zoom collapses this into a single interaction — critical for incident response where triage speed is measured in seconds.

Feature 3 of 11 GA AWS · CloudTrail · Forensics
Enhanced Timestamp Precision for CloudTrail Logs

CloudTrail summary logs now support millisecond-level timestamp precision, providing significantly more granular visibility into the exact timing of cloud API events.

What's new

  • A new Event time field has been added to the CloudTrail summary log table, displaying timestamps at millisecond precision
  • Timestamps in the console now display millisecond precision with improved formatting and tooltips

This update is particularly valuable for correlating rapid sequences of events during active incidents — where standard second-level timestamps are insufficient to determine the precise order of operations when multiple API calls occur within the same second.

Forensic impact: In credential theft scenarios, attackers frequently execute reconnaissance API calls in rapid succession (e.g. ListBuckets → GetBucketPolicy → ListObjects within milliseconds). Millisecond timestamps allow analysts to reconstruct the exact attack sequence and correlate with Polygraph anomaly timings — a significant improvement for post-incident investigation accuracy.

Feature 4 of 11 GA Threat Detection · CIEM · CWPP
New Detection: Anomalous Cloud API Discovery Spikes for Compromised AWS Keys

A new Composite Alert detection now identifies anomalous spikes in AWS discovery and sensitive API activity originating from a single identity. This detection surfaces potential account misuse, reconnaissance, and destructive behaviour when a user or principal suddenly performs significantly more inspection, storage access, or configuration queries than their established normal baseline.

Detection logic

The detection leverages the FortiCNAPP Polygraph's per-identity API behavioural baseline (API Behavior analysis group). When an identity's API call volume or call type distribution deviates sharply from its established baseline — specifically in discovery-oriented calls — the Composite Alert engine fires a correlated finding.

Attack scenarios covered

  • Compromised AWS access keys: Attacker acquires valid IAM access key (e.g. via exposed GitHub repository, supply chain attack, SSRF) and immediately begins cloud reconnaissance — DescribeInstances, ListBuckets, GetSecretValue, ListRoles in abnormal volume
  • Privilege escalation reconnaissance: A legitimate identity whose permissions have been escalated then queries services outside their normal scope
  • Pre-exfiltration enumeration: Targeted enumeration of S3 buckets, RDS instances, and Secrets Manager secrets immediately before data exfiltration
  • Destructive activity staging: Identifying and mapping resources before executing a destructive action (e.g. ransomware encryption of S3)
Detection accuracy: Because this detection is based on deviation from the individual identity's baseline — not a fixed threshold — it fires on anomalous behaviour for that specific identity. A DevOps engineer who always runs discovery APIs will not trigger this; an identity that has never performed discovery calls suddenly running 200 in ten minutes will.
PreSales positioning: This is a clear example of FortiCNAPP's Polygraph-first advantage — IOA-based tools require a known attack pattern to match; FortiCNAPP fires on the behavioural deviation before the attacker takes destructive action. The detection fires during the reconnaissance phase, not after exfiltration.

Feature 5 of 11 GA AWS · CloudTrail · Platform UX
Redesigned AWS CloudTrail Log Page

The AWS CloudTrail Log page has been fully redesigned with a structured, multi-tab layout, providing a more intuitive and efficient forensic investigation experience.

Key improvements

  • Visual dashboard tab: Quick overview of CloudTrail activity — total API calls, identity distribution, service breakdown — at a glance
  • Filtered, paginated event logs: Structured log view with server-side filtering by identity, service, event type, and time range — easier to navigate large CloudTrail datasets
  • User-level investigation tools: Dedicated view to target a specific IAM identity and see all their CloudTrail activity in context
  • Correlated views: Tabs for API errors, Polygraph analysis, and Threat Alerts directly linked to the CloudTrail context — the full detection picture without switching pages
  • Performance: Tabbed data loading reduces time to render large datasets — only the active tab data is fetched on load
  • Saved views and share links: Save a filtered CloudTrail view and share it directly with teammates — essential for collaborative incident investigation
  • Deep linking from alerts: Clicking an alert now navigates directly to the relevant CloudTrail time window and identity, pre-filtered — eliminating manual reconstruction of context
Console navigation: Cloud Logs → AWS CloudTrail. Note the redesigned GCP Audit Log and Azure Activity Log pages followed in the May 2026 release, completing the cloud log page redesign across all three major CSPs.

Feature 6 of 11 GA CWPP · SOC · Alert Intelligence
Detection Intelligence: Observation Details

FortiCNAPP now provides remediation and action-oriented context directly inside alerts through four new Observation Details tabs. These tabs surface the full analytical context behind a Composite Alert finding — exactly where analysts need it, without leaving the alert view.

FortiCNAPP Composite Alerts are built from correlated observations across multiple detection pipelines (user behaviour, API activity, resource changes, historical baselines). While this makes detection more accurate, it has previously required analysts to mentally reconstruct context across multiple data sources to understand what to do. The new tabs close that gap.

Description
Explains what the detection represents, the attacker behaviour it identifies, and the associated MITRE ATT&CK tactics. Answers: What is this alert telling me?
Triage Steps
Recommended investigation flow — what to verify, which logs to review, how to assess scope and impact. Answers: What should I do first?
Remediations
Phased response approach covering containment, eradication, and recovery. Answers: How do I stop this and clean up?
False Positive Notes
Known legitimate activities that can trigger this detection. Answers: Could this be benign? What should I rule out first?

Example in practice: An observation such as "Enumeration of local system accounts detected" previously raised questions about severity, intent, and priority for teams managing high alert volumes. The new tabs answer these questions directly in the alert: Description gives the attacker TTP context, Triage Steps walks through the investigation, Remediations outlines the response, and False Positive Notes highlights legitimate admin tooling that can trigger this rule.

SOC efficiency impact: This is one of the most significant alert quality improvements in the platform's history. Context that previously required tribal knowledge, external runbooks, or FortiGuard research is now embedded directly in every alert. Reduces mean time to triage and removes the skill-level dependency on individual analyst experience for incident response.
MITRE ATT&CK integration: The Description tab includes MITRE ATT&CK tactic and technique mapping directly in the alert context — connecting FortiCNAPP detections to the broader threat intelligence framework without requiring the analyst to look up mappings externally.

Feature 7 of 11 Public Preview Code Security · AI Security
AI-Vendor Secret Detection

FortiCNAPP Code Security SCA scanning can now detect AI vendor API keys and secrets hardcoded in source code, configuration files, and dependency manifests. As AI API keys become as sensitive as cloud access keys — providing direct billing access and data exposure risk — their inclusion in secrets detection is both timely and architecturally significant.

Detections surface in Code Security → Vulnerabilities → Hard-coded secrets alongside existing cloud provider and SaaS secret detections.

Public Preview: This feature is in Public Preview as of the April 2026 release. The coverage set may expand to additional AI providers before GA.
AI Security positioning: Combined with the May 2026 Bedrock LQL policies and the FortiCNAPP AI-SPM capabilities, this establishes FortiCNAPP as the only platform with end-to-end AI security coverage: AI secret detection in code → AI workload posture management → Bedrock runtime detection. No standalone CNAPP covers this full arc.

Feature 8 of 11 Public Preview Code Security · Shift Left
Viewing Non-Default Branch Assessments in Code Security

Code Security now supports viewing security assessments for non-default branches. Users can select and view IaC, SCA, SAST, and Secret scan results from branches other than the primary or default branch, enabling visibility into the security posture of feature branches and development work before it is merged.

Console navigation

Non-default branches can be selected in Code Security → Applications → Repositories to review application scanning assessments, including:

  • Details of vulnerable components (SCA)
  • Third-party vulnerabilities
  • Internal code weaknesses (SAST)
  • Hard-coded secrets
Public Preview in April 2026 → GA in May 2026: This feature entered Public Preview in the April 2026 release and was promoted to Generally Available in the May 2026 release. If you are on the May 2026 release or later, this feature is fully GA.

Feature 9 of 11 Public Preview Code Security · CI/CD
Unified CI/CD Integration Documentation for GitHub — IaC and SCA

The Code Security CI/CD integration documentation for GitHub has been unified, consolidating the previously separate IaC scanning and SCA scanning documentation into a single, streamlined integration guide.

Previously, teams integrating FortiCNAPP Code Security into GitHub Actions needed to consult two separate documentation paths — one for IaC scanning and one for SCA. This consolidation means a single GitHub Actions workflow can now be configured and documented from one reference, reducing integration friction and configuration errors.

DevSecOps workflow impact: A single GitHub Actions job running both IaC and SCA scans in parallel (as the CLI supports) is now backed by unified documentation — consistent with the Claude Code plug-in's parallel IaC + SCA scan behaviour.
↗ Tutorial with GitHub Actions
Feature 10 of 11 Public Preview Code Security · SAST · Windows
SAST Scanning Support for Windows

FortiCNAPP Code Security SAST (Static Application Security Testing) scanning now supports Windows environments. Previously available only on Linux and macOS, SAST scanning can now be run natively on Windows.

Supported Windows surfaces

  • Windows command line (CLI): The lacework codesec CLI runs SAST scans natively on Windows
  • VS Code extension on Windows: SAST findings surface inline in VS Code running on Windows — consistent with the existing Linux/macOS VS Code extension experience
  • Cursor IDE on Windows: The Cursor IDE extension also benefits from Windows SAST support
Public Preview: Windows SAST support is in Public Preview as of the April 2026 release.
Enterprise coverage: Many enterprise development teams run Windows-based developer environments, particularly in financial services, healthcare, and government sectors. Windows SAST support removes a significant gap that previously required Windows developers to use a separate Linux-based scan step or CI/CD integration to get SAST coverage.

Documentation Update — April 2026

Feature 11 of 11 Docs
API Documentation Moved to FNDN (Fortinet Developer Network)

FortiCNAPP API documentation has been moved to the Fortinet Developer Network (FNDN). FNDN is Fortinet's centralised developer portal, hosting API references for FortiCNAPP alongside API documentation for many other Fortinet products.

This move consolidates FortiCNAPP API documentation with the broader Fortinet developer ecosystem — enabling developers integrating FortiCNAPP with FortiSOAR, FortiAnalyzer, or custom Security Fabric automation to find API references for all Fortinet products in one location.

Access: For information about accessing FNDN, see the FNDN FAQ on the Fortinet Developer Network portal.
