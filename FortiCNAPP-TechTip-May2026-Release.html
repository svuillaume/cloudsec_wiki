Feature 1 of 10 GA CWPP · Runtime
Observation Process Attribution

FortiCNAPP runtime observations — anomalous events surfaced by the Polygraph ML engine — are now fully attributed to the specific process that generated them. Previously, observations could point to a workload or container without clearly identifying which executable or process was responsible for the behaviour that triggered the detection.

With this release, each observation in the console displays the originating process name, PID lineage, and execution path, enabling analysts to immediately identify which binary triggered the alert and trace it back to the application stack.

PreSales impact: Directly strengthens the Day Zero detection story — when a novel threat like a supply chain attack executes an unexpected process, the observation is now immediately attributable, reducing investigation time and removing ambiguity in SOC triage.

  • Applicable to all Linux workloads instrumented with the FortiCNAPP agent (eBPF)
  • Observation details visible in Alerts → Composite Alerts and the Polygraph investigation view
  • Feeds directly into FortiSOAR playbooks for automated containment based on process name

Feature 2 of 10 GA Vulnerability Management
Vulnerability Management Now Supports AlmaLinux

FortiCNAPP vulnerability scanning now supports AlmaLinux — the community-maintained RHEL-binary-compatible distribution that became a primary migration target for organisations moving off CentOS after Red Hat's 2023 CentOS Stream transition.

AlmaLinux versions supported: 8.x and 9.x. CVE detection covers OS packages (RPM), installed software, and active package execution (where the FortiCNAPP agent is deployed and Code Aware Agent is enabled for Active Vulnerability Detection).

  • Agentless scanning via snapshot analysis — no agent required for basic CVE discovery
  • Agent-based scanning with the FortiCNAPP Linux agent unlocks active package execution detection (which packages are actually loaded in memory vs. installed)
  • Results appear in Vulnerabilities → Hosts with AlmaLinux OS version context
Coverage context: AlmaLinux is binary-compatible with RHEL. CVE feeds are sourced from AlmaLinux OS Foundation OVAL data and NVD. RHEL-based enterprise workloads migrated from CentOS 7/8 now have full FortiCNAPP vulnerability coverage.

Feature 3 of 10 GA AI Security
AI Security: Bedrock LQL Policies

FortiCNAPP AI Security now ships purpose-built LQL (Lacework Query Language) detection policies for Amazon Bedrock — AWS's managed generative AI service. These policies monitor Bedrock API activity via CloudTrail and surface anomalous or policy-violating GenAI workload behaviours.

Detection scenarios covered by the Bedrock LQL policy set include:

  • Unusual model invocation volumes or patterns (potential prompt injection campaigns or model scraping)
  • Bedrock API calls from unexpected identities or source IPs deviating from the established baseline
  • Anomalous cross-account or cross-region Bedrock access patterns
  • Access to Bedrock knowledge bases or agents outside established access patterns

Policies are available as standard built-in policies and can be cloned and customised using the FortiCNAPP LQL editor for environment-specific AI governance requirements.

AI Security positioning: This is the second FortiCNAPP AI Security capability following AI-SPM (AI Security Posture Management). Bedrock LQL extends FortiCNAPP coverage into GenAI runtime behaviour — detecting threats in AI workloads the same way Polygraph detects threats in traditional cloud workloads: by deviation from a behavioural baseline, no signature required.

Feature 4 of 10 GA Code Security
Viewing Non-Default Branch Assessments in Code Security

FortiCNAPP Code Security can now display vulnerability assessment results for non-default branches (e.g. feature branches, release branches, hotfix branches) in addition to the default branch (typically main or master).

Previously, Code Security assessments — covering SCA (open-source dependency vulnerabilities), SAST (static analysis findings), IaC misconfigurations, and secrets detection — were surfaced for the default branch only. This meant vulnerabilities introduced in feature branches were invisible to FortiCNAPP until they were merged.

With this GA release, security teams can:

  • Navigate to any scanned branch in the Code Security repository view and review findings specific to that branch
  • Identify vulnerabilities before merge — enabling genuinely shift-left triage without waiting for PR approval
  • Compare branch-level risk posture across development streams in active repositories
Shift-left impact: This closes the gap between repository scanning and developer workflow. A critical dependency CVE introduced in a feature branch is now visible in FortiCNAPP before it reaches the default branch, reducing mean time to fix and preventing vulnerable code from entering production.

Feature 5 of 10 GA Kubernetes · GKE
Low Latency GKE Audit Log Violation Policy Evaluation and Alerts

GKE (Google Kubernetes Engine) audit log violation policy evaluation now runs at significantly reduced latency — moving from batch-period processing to near-real-time evaluation. Alerts for GKE audit log policy violations are surfaced in the FortiCNAPP console within minutes of the triggering event rather than within the previous longer processing window.

This enhancement applies to all GKE audit log policies, including:

  • Kubernetes RBAC modification detections (role/clusterrole binding changes)
  • Unauthorised API server access patterns
  • Pod creation with elevated privileges or HostPath volume mounts
  • Service account token misuse and impersonation events
  • Custom LQL policies using the LW_ACT_K8S_AUDIT datasource

The implementation leverages the existing GCP Pub/Sub-based audit log ingestion path, which routes logs to FortiCNAPP within minutes of generation — the same low-latency mechanism available for GCP cloud audit logs since an earlier release.

Prerequisites: GKE cluster must be integrated with FortiCNAPP via the GKE audit log integration (not the Storage-based path). See Kubernetes Audit Logs for GKE for integration setup.

Feature 6 of 10 GA Vulnerability Management
Vulnerability Management Now Supports ChainGuard Wolfi Images

FortiCNAPP vulnerability scanning now supports container images built on ChainGuard Wolfi — a minimal, security-hardened Linux distribution specifically designed for container and cloud-native workloads. Wolfi is maintained by Chainguard and is the foundation for Chainguard Images, a growing ecosystem of minimal distroless base images widely adopted for supply chain security hardening.

Wolfi images present unique scanning challenges because they use the APK package format (from Alpine), do not include a traditional OS CVE feed, and often exclude packages entirely from the final image layer. FortiCNAPP now correctly:

  • Identifies Wolfi as the base OS and selects the appropriate package database (Wolfi SBOM / Chainguard advisory feed)
  • Scans installed APK packages for known CVEs against the Wolfi advisory database
  • Correctly handles minimal/distroless Wolfi images that contain zero OS packages and reports them as low-risk baselines accurately
Supply chain security context: Chainguard Wolfi images are explicitly adopted to reduce CVE surface area. FortiCNAPP's Wolfi support allows organisations to verify that their Chainguard adoption is achieving the intended reduction in vulnerability exposure — and surfaces any CVEs present in application-layer packages that Wolfi does not itself eliminate.

Feature 7 of 10 GA CWPP · Runtime
Threat Observations Policies Page

FortiCNAPP introduces a dedicated Threat Observations Policies page — a new console section that centralises all policies governing how the Polygraph ML engine and CWPP agent surface threat observations. Previously, observation-related policies were distributed across multiple locations in the Posture Policies section.

The new page provides:

  • A single view of all policies that produce threat observations — separated from compliance and misconfiguration policies
  • Policy status, severity, and last-triggered context for each observation policy
  • Ability to enable, disable, or customise observation policies from a single location
  • Direct linkage between an active observation in the alert view and the governing policy that produced it

Console navigation: Policies → Threat Observations

Operational value: This is a policy management UX improvement that reduces the time to understand why an observation was generated — which policy fired, at what threshold, and whether the policy is tuned for the current environment.

Feature 8 of 10 GA Platform UX · Cloud Logs
Redesigned GCP and Azure Cloud Log Pages

The GCP Audit Log and Azure Activity Log pages in the FortiCNAPP console have been redesigned with an updated interface. These pages are the primary entry points for investigating cloud control plane activity — API calls, identity actions, and resource modifications ingested from GCP and Azure respectively.

The redesigned pages introduce:

  • Updated layout consistent with the previously redesigned AWS CloudTrail log page (April 2026 release)
  • Improved filtering controls — filter by identity, resource, action type, time range, and severity in a single unified filter panel
  • Enhanced Polygraph integration — cloud log events are directly linked to the Polygraph visualisation, showing where each event falls on the behavioural baseline
  • Faster load times and improved pagination for large-scale cloud environments

Console navigation: Cloud Logs → GCP Audit Log and Cloud Logs → Azure Activity Log

Feature 9 of 10 GA Kubernetes · CWPP
Agent Support for Kubernetes on Cloud Platforms

The FortiCNAPP Linux agent now has expanded Kubernetes support across managed cloud platforms — covering EKS (AWS), AKS (Azure), and GKE (GCP) in addition to self-managed Kubernetes clusters. This release resolves agent compatibility gaps that existed for specific managed Kubernetes node configurations and Kubernetes versions on cloud provider-managed node pools.

Key improvements:

  • Agent DaemonSet deployment validated across EKS (Bottlerocket and Amazon Linux 2023 nodes), AKS (Ubuntu and Azure Linux nodes), and GKE (Container-Optimised OS and Ubuntu nodes)
  • Correct process-level eBPF telemetry collection on Kubernetes nodes running Linux kernel 4.14+
  • Support for auto-scaling node groups — agent automatically onboards new nodes as they are provisioned and de-registers gracefully on node termination
  • Helm chart updated to support platform-specific tolerations and node selectors out of the box
Deployment references: Full deployment procedures for each platform are documented at Installing Linux Agent on Kubernetes and How FortiCNAPP Derives the K8s Cluster Name.

Public Preview — May 2026

Feature 10 of 10 Public Preview Code Security
Code Security Claude Code Plug-in — Public Preview

The FortiCNAPP Code Security plug-in for Claude Code enters Public Preview. The plug-in is available in the Claude Code marketplace and brings FortiCNAPP IaC and dependency scanning directly into the Claude Code agentic development workflow.

When installed, the plug-in automatically scans:

  • Infrastructure-as-Code (IaC) files — Terraform, CloudFormation, Kubernetes manifests, Helm charts — for security misconfigurations using FortiCNAPP IaC policies (Rego/Opal engine)
  • Dependency files (SCA) — package.json, requirements.txt, go.mod, pom.xml etc. — for known CVEs using FortiCNAPP's SCA engine

Key behaviour: IaC and SCA scanners launch in parallel on the project directory when the plug-in is invoked — minimising scan latency in Claude Code sessions. Findings are surfaced as natural-language security findings inline in the Claude Code workflow, with severity, policy reference, and direct remediation guidance.

Installation: Available in the Claude Code marketplace. Requires a FortiCNAPP Code Security license.

Public Preview notice: This feature is in Public Preview as of the May 2026 release. It was previously listed as Public Preview in the April 2026 release notes. Public Preview features are available for customer evaluation but may be subject to change before General Availability. Provide feedback via the FortiCNAPP community portal.
IDE extension ecosystem: The Claude Code plug-in joins two existing GA IDE integrations — the VS Code extension and the Cursor IDE extension (both GA, covering SCA, SAST, IaC, and secrets detection). Together these three touchpoints provide FortiCNAPP Code Security coverage across the three most widely adopted AI-assisted development environments.
